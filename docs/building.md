# Building

```sh
rush build
```

`rush build` syncs dependencies if needed, compiles the sources, and writes two files to
`out`:

- `com.example.counter.aix`: the extension, ready to import into App Inventor.
- `com.example.counter.md`: a [reference of its blocks](#generated-documentation).

Intermediate files live in `.rush`. `rush clean` deletes them, and the next build compiles
everything again.

## What's in the AIX

```
com.example.counter/
├── components.json                   the blocks
├── classes.jar                       the extension, compiled to DEX
├── files/
│   ├── AndroidRuntime.jar            the extension and its private libraries
│   └── component_build_infos.json    permissions, manifest entries, libraries
├── aars/                             shipped AARs and resources
├── assets/                           files listed under assets in rush.yml
└── aiwebres/                         the icon and license
```

## Java and Kotlin versions

Java sources are compiled with Java 17's language level, so records, switch expressions,
text blocks, sealed classes and `var` all work. Kotlin sources are compiled with
`kotlin.compiler_version` from `rush.yml`. Projects can mix both.

The bytecode is desugared for the extension's `min_sdk`, so language features work on
every Android version the extension supports. Newer Java APIs are a different matter:

- With `min_sdk` 24 or higher, Rush also desugars the core library, so `java.time` and
  other Java APIs added after Android 7 work on every Android version from `min_sdk` up.
  Rush bundles only the parts of the backport library the extension uses.
- Below 24, only APIs present on the device are available. Check each API's Android
  version in the Android documentation.

## Optimizing

```sh
rush build --optimize
```

`--optimize` runs [R8](https://developer.android.com/topic/performance/app-optimization/enable-app-optimization)
over the extension and its private libraries, AARs' code included, to shrink, optimize
and obfuscate them. R8
runs in ProGuard compatibility mode, so rules written for ProGuard keep their meaning. It
reads:

- `src/proguard-rules.pro`,
- consumer rules shipped by dependencies (`proguard.txt` in AARs, `META-INF/proguard/`
  in JARs).

The rules generated by `rush create` keep the extension's classes and dropdown enums,
which App Inventor calls by name. Rush adds Android's default rules (Parcelable
`CREATOR`, enum `values`/`valueOf`, native methods, View accessors, `onClick` handlers,
JavaScript interfaces) and keeps the classes that manifests and private AARs' resources
name. It also lets code reference the `R` classes of Android libraries, which App
Inventor generates when it builds the app. Add `-keep` rules for anything else your code reaches by reflection.

Rush moves the optimized classes under `<package>.repacked`, so they can't clash with
another extension's: don't set `-repackageclasses` yourself (`rush migrate` removes it
from older projects). Optimized builds also write `out/<package>.mapping.txt`, the
mapping of renamed classes, to read stack traces from the extension.

Without `--optimize`, private libraries are still shrunk to the code the extension uses,
but nothing is renamed or optimized, and signatures, annotations, Kotlin metadata and
Kotlin's null checks are kept. With it, R8 removes Kotlin's null checks, as in Android
release builds.

In both cases, a class that shipped code uses but nothing ships fails the build with
R8's `Missing class` error. Add the library that provides it to `dependencies`, or, if
that code never runs, add `-dontwarn` rules for it to `src/proguard-rules.pro`. When the
class is missing from a library apps get in an older version, Rush names that library
and the rule, such as `-dontwarn androidx.annotation.**` for annotations App Inventor's
AndroidX lacks.

## Generated documentation

Every build writes `out/<package>.md`, a Markdown reference of the extension's blocks.
It has a section per component, with its events, methods, properties and dropdowns,
taken from the block descriptions, parameter names and types. Deprecated blocks are left
out. It's ready to paste into a forum post or a repository's README, and
[the GitHub workflow](github-actions.md) attaches it to releases.

Part of the generated reference for the counter from
[Writing extensions](writing-extensions.md):

```markdown
### CountAssetSize(asset)

Counts the bytes of an asset without blocking the app.

| Parameter | Type |
|---|---|
| asset | text |
```

## Build cache

Rush skips compiling and generating DEX bytecode when nothing they depend on changed: the
sources, assets, dependencies, `rush.yml`, the manifest, the JDK and Rush itself. It
compares file contents, not modification times, so a skipped build produces exactly the
same AIX as a clean one.

Desugared libraries are cached in `cache/desugar` of Rush's home (where the installer put it) and shared by all your projects.
`rush clean` keeps them; delete that folder to free the space. Resolved dependencies and
the core library backport are kept in `.rush`. If a build behaves strangely after manual
changes to these files, run `rush clean`.
